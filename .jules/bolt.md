## 2024-10-24 - Fused QKV Attention Projection
**Learning:** In a CausalSelfAttention implementation with separate c_q, c_k, and c_v linear projections, kernel launch overhead and memory bandwidth utilization can be slightly improved by fusing them into a single `c_qkv` projection.
**Action:** Always look to fuse separate, identically-sized parallel linear operations applied to the same tensor input (especially Q, K, V attention projections) into a single larger projection, splitting the result afterwards.

## 2024-10-25 - Optimizer Parameter Loop Hoisting
**Learning:** In fused PyTorch optimizers such as AdamW, filling tensor variables for group-level constants inside the parameter loop adds unnecessary CPU cycle overhead per training step.
**Action:** Always hoist group-constant scalar tensor updates (e.g., `.fill_()` for learning rate, betas, epsilon, and weight decay) out of the parameter loop to reduce CPU cycle overhead, while keeping per-parameter state updates (like `step`) inside the loop.
## 2024-10-26 - O(N) Dataloader Packing
**Learning:** In `prepare.py`'s dataloader logic, finding the largest document that fits in the remaining space of a row via a linear scan across `doc_buffer` causes an O(N) CPU bottleneck per batch. We can optimize this by maintaining parallel sorted lists for `doc_lens` and `doc_tensors`, replacing the linear scan with an O(log N) `bisect` lookup. Also, converting lists to PyTorch tensors during the `refill_buffer` step instead of the packing loop hoists memory allocations out of the hottest path.
**Action:** When implementing best-fit or greedy packing algorithms that scan over large buffers in PyTorch data loaders, use `bisect` on sorted lists to reduce the lookup complexity to O(log N). Pre-allocate or convert intermediate list data into `torch.tensor` before the main packing loop to avoid CPU overhead during batch formation. Always use `bisect_right` followed by `bisect_left` to strictly preserve chronological tie-breaking if required.
